# ballware Storage Service — documentation

This folder documents the Storage Service from the backend side: its HTTP API surface, request/response
payloads, storage data model, provider behavior, tenancy and authorization behavior, and the OpenAPI
snapshots the pages are derived from.

> Scope note: this is the **backend view** of the service. Setup, configuration and Docker usage stay
> in the repository [README.md](../README.md). The frontend consumption contract (how attachment and
> temporary metadata are interpreted by the UI framework) lives in `ballware-angular/docs/metadata`
> and is not duplicated here.

## Quick facts

- Two OpenAPI documents: `storage` ("ballware Storage User API", 6 paths, 1 schema) and `service`
  ("ballware Storage Service API", 12 paths, 1 schema), OpenAPI `3.0.1`
  (`src/Ballware.Storage.Service/Startup.cs:186-198`).
- Swagger UI: `https://localhost:6005/swagger` (`src/Ballware.Storage.Service/Startup.cs:279-288`);
  raw documents at `/swagger/storage/swagger.json` and `/swagger/service/swagger.json`.
- Committed OpenAPI snapshots: [openapi/storage.json](openapi/storage.json),
  [openapi/service.json](openapi/service.json), generated by
  [openapi/fetch-spec.sh](openapi/fetch-spec.sh).
- Mounted routes: `/storage/attachment` and `/storage/temporary`, each mapped once for the user API
  and once for the service API (`src/Ballware.Storage.Service/Startup.cs:263-266`).
- Ports: Development HTTP `http://localhost:5005` / HTTPS `https://localhost:6005`
  (`src/Ballware.Storage.Service/appsettings.Development.json:8-20`); the container image exposes
  5000/5001 (see repository `README.md`); `ballware-docker-compose` publishes `5005`
  (`docker-compose.yml:201-204`).
- Authentication: JWT bearer against an OIDC issuer; authorization by scope → policy (`storageApi`
  for User API operations, `serviceApi` for Service API operations,
  `src/Ballware.Storage.Service/Startup.cs:105-121`). Claims used: `tenant`, `sub`, `right`
  (`src/Ballware.Storage.Service/Configuration/AuthorizationOptions.cs:14-24`).
- JSON bodies are PascalCase (`src/Ballware.Storage.Service/Startup.cs:136-151`).
- Uploads are `multipart/form-data` with part name `files` (`files[]` in the Angular client); request
  body limit is 40 000 000 bytes (`src/Ballware.Storage.Service/appsettings.json:35-39`).

## Request flow

```text
client (browser / other service)
  |  Authorization: Bearer <token>
  v
ASP.NET Core routing + JWT bearer authentication          Startup.cs:89-103, 258-261
  |  scope claim -> policy "storageApi" / "serviceApi"    Startup.cs:105-121
  |  (anonymous: GET download routes carry no policy)     AttachmentEndpoint.cs:35-41, TemporaryEndpoint.cs:25-33
  v
endpoint handler
  |  User API: tenant resolved from the "tenant" claim    AttachmentEndpoint.cs:166,173,203,226
  |  Service API: {tenantId} from the path, {userId}
  |  recorded as "behalf of user" for audit fields
  v
storage provider (Azure Blob or S3, blob path
  {tenantId}/{entity}/{ownerId}/{fileName})                Provider.Azure/…, Provider.S3/…
  +
tenantable repository (WHERE tenant_id = …, audit fields
  from userId, no rights check)                            Data.Ef/Repository/…, Ballware.Shared.Data.Ef
  v
EF Core on the metadata DB (postgres | mssql)             Data.Ef.Postgres/…, Data.Ef.SqlServer/…
  v
Quartz temporary-cleanup job (expired temporary entries)  Jobs/Internal/TemporaryCleanupJob.cs
```

For setup and configuration see the repository [README.md](../README.md). For OpenAPI regeneration see
[openapi/README.md](openapi/README.md).
